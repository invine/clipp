# Source context for UX implementation planning

Inspected 2026-10-10. Facts and candidate grouping inputs, not approved implementation decisions. [Baseline receipt](planning-baseline.json). No source edits, tests or native actions were performed during charting.

## Reusable source boundaries

| Boundary | Observed facts and anchors | Decision it informs |
| --- | --- | --- |
| Shared app and task state | [ClipboardApp](../../packages/ui/src/ClipboardApp.tsx) combines History, navigation, forms, QR and recovery presentation. [ManagedRelaySettings](../../packages/ui/src/ManagedRelaySettings.tsx) already awaits mutations and owns busy/error state, but drafts live in mounted component state. | Define authoritative data, action results and session task/draft ownership before cutover; avoid requiring a blanket rewrite or global framework. |
| Runtime projections | [Electron renderer](../../apps/electron/src/renderer.tsx) consumes getState/onUpdate; [Android entry](../../apps/android/src/main.tsx) consumes client state/listeners; [Chrome background](../../apps/extension/src/background.ts) already projects Clips/devices/settings/requests/relay state. | All affected consumers need authoritative updates and compatible action contracts. Chrome needs a complete consumer, not necessarily a new state backend. |
| Chrome divergence | [Popup](../../apps/extension/src/popup.tsx) consumes the shared app; [options](../../apps/extension/src/options.tsx) and its [History component](../../apps/extension/src/components/ClipHistoryList.tsx) duplicate partial product state. Settings currently send the entire stale local object although background accepts validated partial patches. | Some urgent state corrections can survive later full-page consolidation. Plan a clear retirement boundary rather than two permanent full product UIs. |
| Chrome routing and capabilities | [Manifest](../../apps/extension/manifest.json) already has an options page. [Trusted UI check](../../apps/extension/src/managedRelayUi.ts) requires exact popup/options URLs and matching extension ID; settings and relay actions use it. [Share Now boundary](../../apps/extension/src/popupClipboardActions.ts) is popup-only. | Decide destination messaging/reuse/stale targets/focus without weakening authorization. Shared rendering must respect per-surface capabilities. Full-page parity must precede redirecting long tasks there. |
| Visual foundation | [UI entry](../../packages/ui/src/index.ts) imports [shared CSS](../../packages/ui/src/styles.css); direct component imports can miss styles. Current CSS also contains global sizing, remote fonts/icons and hardcoded dark colors; runtime wrappers contribute their own backgrounds. | Extract/reuse semantic styles and local icons with explicit host integration. Importing all current global CSS into options is not by itself a safe migration. |
| Native boundaries | [Android Activity](../../apps/android/android/app/src/main/java/com/clipp/app/MainActivity.java), [client](../../apps/android/src/client.ts), [scanner](../../apps/android/src/qrCameraScanner.ts) and [continuity notification](../../apps/android/android/app/src/main/java/com/clipp/app/BackgroundContinuityService.java) own behavior outside React. Scanner overlay and native provider lifecycle need explicit handling. | Insets/IME/Back, provider safety, notification destinations and permission recovery cannot be resolved by CSS alone. Keep scanner diagnosis environment-qualified. |
| Routine additions | [Clipboard runtime factory](../../packages/core/runtime/clipboard.ts) already accepts sharingLifetimeMs; runtime calls need the actual persisted setting. [Identity presentation](../../packages/core/trust/identity.ts) already supports alias clearing. | Lifetime needs validated settings/wiring, and alias clearing needs an honest UI path; neither requires reinventing Clip or identity semantics. |
| Manual reset | [Identity rotation](../../packages/core/trust/identityRotation.ts) currently handles revocation/Identity Loss. It does not supply the approved voluntary durable intent and former-public-ID receipt. | Plan a separate durable core/host lifecycle, restart and fault acceptance. A new button around automatic rotation does not satisfy the contract. |

Mutation rejection is not universally rollback. For example, [Chrome relay removal](../../apps/extension/src/managedRelayConfiguration.ts) may erase credentials before configuration persistence fails. The plan must reconcile actual effects. Likewise, the manual tray follow-up did not reproduce the original Dock issue: retain revalidation before prescribing a repair.

## Verification to reuse

- [Routine verification](../../docs/agents/verification.md): npm and Node ≥22.22.1; current pin 24.16.0. `npm run verify` runs lint, all-runtime typechecks/Jest and all three production builds. `npm run check` is required before code commits. Record the exact candidate and dirty state; these commands were not run for charting.
- [Extension scripts](../../apps/extension/package.json) provide clipboard, integration, Pairing-response, offscreen-storage, managed-relay and relay-acceptance checks outside routine verify. Select meaningful checks for the affected behavior rather than treating every command as interchangeable.
- The [clipboard regression script](../../apps/extension/scripts/verify-clipboard-io.mjs) uses a popup document as a tab, not the actual toolbar popup. Its visible-text selectors need adaptation to accessible icon names when changed. It writes the process-wide clipboard and best-effort restores only readable text: run it only in a fresh coordinated interval or suitable isolated desktop.
- [Electron acceptance](../../docs/electron-relay-acceptance.md), [Chrome acceptance](../../apps/extension/README-managed-relays.md) and [Android acceptance](../../docs/android-managed-relay-native-acceptance.md) retain separate native/account/transport prerequisites. Web builds and storage fixtures are not real notification, permission, full-app Pairing or OAuth passes.
- The accepted [layout matrix](../ux-study/layout-state-contract.md#implementation-acceptance-matrix), [control contract](../ux-study/control-flow-contract.md) and [native gap ledger](../ux-study/remaining-native-coverage.md) are mandatory inputs to each affected execution ticket. The final planning decision will distinguish ticket-completion evidence from external qualification ownership without silently waiving either.
