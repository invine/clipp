# UX finding register

This register retains **all 51 runtime findings** and records the approved priority order and proposed ownership for the [handoff](handoff.md). The user approved correctness → compact workspace → additions; observed High/Medium labels in the dated reports remain unchanged. A medium finding may join band 1 because it shares a repair with a blocked task or lacks a reliable recovery route.

**Read each row with its linked report section.** That canonical section supplies the precise scenario/reproduction, viewport/scaling/mode, actual versus expected behavior, screenshot/trace/source pointers and confidence qualifications; the report's evidence header supplies its exact source/build receipt. The row below adds proposed implementation ownership and acceptance. This avoids rewriting or weakening native/fixture qualifications. Source line numbers in old prose are approximate; follow the linked file and named handler against the receipt (for example, the Chrome options settings writer is `handleSettingChange`, currently near line 119, not the older line 134 reference).

Evidence scopes qualify confidence: native isolated results apply only to the tested environment/action boundary; fixtures establish UI response to synthetic inputs, not a real transport/storage/account outcome. Every observed rendering claim remains supported; no untested platform receives an inferred pass. Priority is driven by task blockage, data/sharing consequences, likely task frequency and evidence strength; prevalence outside the sample is unknown.

The [native host follow-up](native-host-observations.md) adds supporting evidence without changing the 51-finding count. In particular, a real cold-offline Chrome popup reproduces E01's shared external-icon failure. Normal restart persistence, offscreen recreation, forced worker stop/wake and initial-view native Escape now have bounded evidence; these do not qualify authenticated journeys, natural idle suspension, nested-task behavior or OS clipboard writes.

The [live-journey follow-up](live-journey-observations.md) adds a real local Pairing rejection to C07: options ignores the `ok:false` response after importing its own generated target. QR generation/software decode and guarded QR Copy agree; that round did not qualify OS clipboard or two-device behavior. The original folder has a path-derived ID mismatch; an explicitly approved disposable fixed-ID copy now matches the registered callback. Real sign-in entry and cancellation are observed; the user deferred completion after a reported Google browser rejection, and authenticated readiness remains unverified.

The [non-account native continuation](native-host-continuation.md) adds nested popup Escape/draft loss, user-observed click-away, passive close-to-tray, actual SQLite contention/retry and Identity Loss/automatic relaunch. It supports E02/C12 and qualifies E17 with conflicting manual evidence; the register retains 51 historical findings.

The [sign-in-free continuation](sign-in-free-journeys.md) strengthens E11/E12/E16/C07 with real signed Pairing/failure observations. Its coordinated clipboard interval verifies Electron native text capture and retained-Clip Copy in both hosts, while preserving Chrome read-focus and deliberate permission-recovery gaps. The sparse native error notice adds a 152px space-cost case to C04; it is not the earlier dense-history overlap. All owned hosts are closed.

Owners name code layers, not individual assignees. Shared UI is `packages/ui`; cross-runtime behavior belongs in `packages/core`; runtime integration belongs in `apps/electron`, `apps/extension` and `apps/android`. All shared changes require relevant runtime bridges and acceptance.

## Acceptance qualifications

- Approved new behavior is not already implemented. The prototype is incomplete for the final task/draft/issue contract and is never evidence of native transfer or safe destructive reset.
- Full-page Chrome must be functional before redirecting management there. Route handoff covers current query/context, stale destinations, focus and unsaved full-page drafts while preserving trusted-page checks.
- Retry/failed save does not imply every operation rolls back: relay removal may erase credentials before configuration persistence fails. Reconcile authoritative state and offer the correct recovery.
- Clear all affects pinned/filtered-out local history. Single Delete has immediate failure/Retry, no confirmation and no Undo promise. Unpin may trigger retention; disappearance must be explainable.
- Long-value reachability is not the same as showing every character in a collapsed row. Full values must be deliberately inspectable/copyable; previews may truncate.
- Uniform wide card heights remain approved. Enlarged text must use enough shared height, fewer columns or narrow rows; do not silently introduce masonry.
