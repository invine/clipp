# Clipp user flows and control coverage

Date: 2026-10-07. Resolution asset for [Inventory user flows and control coverage](issues/02-inventory-flows-and-controls.md).

This is a source-based inventory of reachable controls, their runtime handlers and the scenarios the visual studies must exercise. It confirms several missing or ineffective controls, identifies existing capabilities whose UI is incomplete, and separates them from new product decisions. No application, personal profile, clipboard or native notification was exercised. Screen appearance, geometry and native lifecycle outcomes remain unverified.

The study follows the user's direction: shared styling and terminology, layouts adapted to each runtime, simple defaults and compact daily use. No redesign or change to an accepted domain contract is approved here.

- HEAD: `a2e1a64cad05eadb7c567b48e3ec45ce7cd51e33`; branch: `codex/agent-workflow-integration`; Node: `v24.16.0`.
- [Source baseline](inventory-source-baseline.json) records SHA-256 hashes for 145 files in explicitly selected production/specification scopes, the source diff hash and the collection time. It is an inventory of scope, not a claim that every file received equal inspection.
- The only modified production source in those scopes was `apps/electron/src/managedRelayAuth.ts`; its working-copy content is represented in the baseline. `tests/electron/managedRelayAuth.test.ts` was also already modified outside these source scopes. Neither was changed for this study.
- Earlier charting observed temporary tray/main changes. Those were absent for this investigation; tray references below use the current main source, where the duplicate commands still exist.
- Claims marked **source-confirmed** follow directly from controls, handlers or CSS. **Runtime risk** requires rendered/native observation. **Contract conflict** identifies contradictory source/requirements without silently choosing new semantics. **Intentional difference** follows the accepted runtime contract.

## Intentional differences and specification conflicts

- E/A durable pins versus extension session pins; E/A polling versus focused-popup/manual Chrome capture; Android foreground-only capture, opt-in continuity and one-resume live-write retry are accepted differences. Historical reconciliation never writes the system clipboard. See [runtime capabilities](../runtime-capabilities/spec.md), [Clip History](../clip-history/spec.md) and [extension clipboard I/O](../extension-clipboard-io/spec.md).
- Shared Copy creates a fresh Local Clip; Share Now overrides Auto Sync for one current-clipboard event. Failure and partial-success feedback must retain this distinction. A successful action is not a remote-delivery acknowledgement.
- Device Name is propagated presentation metadata; Local Device Alias is local-only; Peer ID is identity. User-facing copy should follow [the glossary](../../GLOSSARY.md). No glossary change is required to describe the findings.
- Older relay capability prose still mentions default lists/fixed Android/extension configuration, while current project instructions, controller and UI use empty editable managed configurations. Preserve [accepted single-session fallback](../../docs/adr/0012-relay-transport-fallback-and-concurrent-sessions.md); UI advice must not create per-transport retained-session toggles.
- The extension content-script capture and restart recapture questions already have [named](../extension-clipboard-io/issues/03-align-content-script-capture-capability.md) [tickets](../extension-clipboard-io/issues/02-prevent-restart-recapture.md). Reuse them instead of creating competing ownership. The UX study records actual capture paths and their discoverability; it does not settle their protocol/capability policy.
- Core allows empty alias to clear it, but the shared UI prevents the operation. Core exposes configurable retention while capacity limits are explicitly not end-user settings. Absence of a knob is not automatically a UX defect.
