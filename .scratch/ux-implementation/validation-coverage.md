No tests, applications, native checks, clipboard access, account journeys or production changes were performed for this document. Approved execution-ticket links identify the delivery slices in the [catalog](catalog.json). The [remaining native ledger](../ux-study/remaining-native-coverage.md), [handoff coverage and flow dispositions](../ux-study/handoff.md#coverage-disposition-explicit-carryforward-accepted), [finding register](../ux-study/handoff-findings.md) and [Android coverage boundaries](../ux-study/android-observations.md#coverage-boundaries) are the source of the gaps below. They describe study evidence and its limits, not passes for a changed candidate. ## Classification and completion rules

| Classification | Meaning |
| --- | --- |
| **Candidate** | Required candidate evidence for the affected behavior/ticket. Missing evidence leaves that portion unqualified; a helper test, older study run or fixture cannot replace the specified native/runtime result. |
| **External** | An existing owner retains the capability decision or qualification. Link a concrete dependency only where the implementing ticket consumes it. Do not duplicate, resolve or weaken that owner's acceptance criteria here. |
| **Retained** | A named qualification remains explicitly unverified under the accepted study disposition, including unavailable hardware, deferred participation and broader platform coverage. It is neither a pass nor a waiver. |

**Required if changed:** a retained case becomes required candidate evidence for the affected portion when an implementation changes the behavior or boundary it exercises, relies on it for correctness, or claims it repaired/supported. This applies to the specific export, Sharesheet/selected-text ingress, continuity, native-storage or permission/settings-return boundary changed or relied upon. Ordinary shared-UI, label or layout changes do not automatically reopen accepted participation or unavailable-hardware gaps such as VoiceOver, TalkBack, hardware keyboards and physical foldables. Those dispositions remain retained. If work specifically changes or relies on that platform-specific boundary or claims its qualification, record the missing evidence for that claim explicitly; do not silently waive it or treat ordinary UI migration as resumed user participation. Moving an existing export control does not prove delivery; changing its export path cannot be closed using the old carryforward. If its prerequisite remains unavailable, record the affected portion as blocked/unqualified rather than calling it passed or making unrelated work wait.

Mixed classifications separate a bounded candidate check from broader or external qualification. They do not allow the candidate owner to substitute the retained gap for an approved exit criterion. Shared finding collectors gather contributing native/correctness/workspace evidence before closing the whole finding. A row linking several tickets identifies scoped contributors and the collector; it does not impose the entire row on every predecessor. The individual ticket owns its required output. For example, immediate Pairing contributes action evidence while later outcomes owns the complete native journey; alias clearing belongs to Devices, emitted lifetime to its settings owner, and integrated reset qualification to the final reset ticket.

Record exact candidate revision and dirty state, runtime/build/version, native device/window units, prerequisites, scenario, expected/actual result, evidence link and **passed / failed / not run**. Every row starts with an unverified case; none receives a new pass in this consolidation. Use representative combinations plus known narrow/short/enlarged/failure cases, expanding for concrete failures rather than reproducing historical screenshot counts.

All prior test hosts are closed, clipboard gates are off and display settings were restored. Old clipboard/display/permission intervals are finished. Native clipboard work needs a fresh isolated synthetic-marker interval; global setting changes need a newly coordinated interval. Sign-in remains user-deferred and must not resume merely because an implementation ticket links it. No old Retry, file picker or sign-in action is pending.
