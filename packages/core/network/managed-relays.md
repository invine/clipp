# Managed relay controller contract

`ManagedRelayController` is the shared client seam for the new relay settings model. It starts empty. Runtime adapters persist only normalized `RelayConfiguration` values and renewable credentials; they pass the current list to `setConfigurations` after starting their existing Device Identity host. Existing `RelayLifecycle` and `relayAddresses` callers remain available until each runtime migrates.

The adapter must keep access tokens, refresh credentials and browser login out of renderer/content-script state. `accessToken` is single-flighted by the controller per canonical discovery URL. It must return an access token scoped to that exact endpoint or `null` when explicit login is needed. `interactiveLogin` is called only by `requestLogin`; `openAccount` only opens the portal and must not erase credentials or report revocation. `eraseCredentials` removes only the specified endpoint's local credential on configuration removal or identity-changing replacement.

`discover` must send the bearer token to the exact HTTPS `/v1/relay` URL with no redirects and enforce the 16 KiB JSON response bound. The Go wire response carries `validUntil` as a UTC RFC3339 string. Adapters must call `normalizeDiscoveryResponse` before returning to the controller. The controller validates version, expiry, Peer ID and every complete dialable multiaddr, then refreshes the document at `validUntil`. Unsupported but well-formed transports are filtered by `supportsAddress`. `dial` must return the Noise-verified remote Peer ID; it must never yield a pre-existing direct or unrelated connection as an owned relay candidate. The controller closes wrong-peer and losing candidates before authentication and caps setup at four configurations with two staggered addresses each.

`authenticate`, `reserve`, and `register` operate on that exact connection. The Go authentication wire response carries `sessionExpiresAt` as a UTC RFC3339 string; adapters must call `normalizeRelayAuthResponse` before returning. These helpers reject numeric, non-UTC and malformed timestamps. The adapter must disable any automatic Circuit Relay v2 listener that would reserve before authentication. `reserve` returns a handle whose `release` removes only this relay's listener and keep-alive/redial ownership before the controller closes the owned connection. Keep-alive tag removal is best effort in the legacy lifecycle, so new adapters must also prevent a still-running host from redialing a removed relay. `unregister` is required for late registration compensation and is best effort when the remote service is unavailable; it does not revoke server account grants. Adapters must observe abort signals. If a timed-out reservation still returns a handle, the controller releases it; if registration completes after timeout/removal, the controller compensates with `unregister`. Only an explicit `unsupported_protocol` outcome from v2 registration permits v1 fallback.

The adapter should call `connectionLost(key, connection)` for an owned connection closure. The captured connection argument prevents a stale close event from removing a replacement. `eligibleDialAddresses` filters signed reachability routes by current configured relay ownership without modifying the Signed Peer Record bytes or direct candidates. Runtime adapters retain their existing identity, trust, clip, and history storage.

UI callers pass `states()` and `configurations()` into the optional managed-relay props on `ClipboardApp`, together with add/edit/remove, login, account, and retry actions. Unmigrated callers continue using `relayAddresses` and `onSetRelayAddresses`.

Public configuration mutations synchronously detach affected entries and start each cleanup independently. A re-add waits for prior cleanup of its key and endpoint before acquiring fresh credentials, while unrelated relay removals and stop proceed without waiting for that cleanup. Network setup continues asynchronously, with desired-configuration and per-entry generation checks preventing stale completion from restoring removed state.
`stop()` starts all remaining relay cleanups together and rejects with `deadline_exceeded` after 15 seconds if any cleanup remains pending; a rejected stop does not claim that the pending cleanup completed.
Peer ID ownership remains claimed until its reservation is released and connection is closed, so a conflicting relay cannot authenticate while old resources remain. Failed credential erasure blocks later setup for that same endpoint in the controller. State observers are notifications only; their exceptions cannot interrupt cleanup.
